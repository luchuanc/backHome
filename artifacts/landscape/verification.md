# 自动横屏与局域网试玩验收

2026-09-22。手机进入营地或开始/继续远征的用户手势中启用横屏。

## 实现

- 支持原生全屏及方向锁时，请求 landscape；被拒绝或API不存在时，游戏舞台自动旋转90度。标题页保持自然方向。
- 安全区、地址栏引起的可视区域变化统一进入逻辑视口；UI断点使用容器尺寸，Canvas仍按未旋转的逻辑宽高绘制。
- 摇杆向量和瞄准坐标逆旋转；按钮点击由浏览器处理变换；方向变化会清除活动输入。
- 物理横屏时撤销舞台旋转，返回竖屏重新启用，避免重复旋转。

## 验证

- 全量测试40/40通过，其中12项为新增横屏控制器测试。新增测试覆盖锁屏成功/拒绝/API缺失、同步用户手势全屏申请、安全边距、视觉视口偏移、缩放、点与向量逆旋转、并发请求、销毁清理。
- `npm run check` 通过；独立HTML重新构建并内嵌 viewport.js、viewport.css。
- 实际浏览器390×844：标题保持竖屏，点击继续游戏后逻辑画布844×390、transform为90度；营地、远征、暂停和地图均跟随横转。
- 实际拖动旋转后的摇杆，按钮可进入暂停与恢复。
- 切换844×390：画布仍844×390，transform还原单位矩阵；返回390×844再次90度，没有双重旋转。
- 原来的127.0.0.1电脑存档未重置。验证使用localhost独立来源。
- 本轮浏览器错误/警告日志为空。
- 局域网服务通过 `npm run lan` 启动，监听0.0.0.0:8766；本机实测 http://192.168.31.252:8766/ 返回HTTP200。手机需与电脑处于同一网络，服务保持运行。

## 边界

浏览器尺寸测试与控制器模拟不是实体手机验收。原生系统旋转、iPhone浏览器行为、触摸手感及局域网跨设备可达性需在用户手机实际验证。原生锁方向需要的条件由浏览器决定，软横屏不依赖其成功。参考：[MDN ScreenOrientation.lock](https://developer.mozilla.org/en-US/docs/Web/API/ScreenOrientation/lock)。
